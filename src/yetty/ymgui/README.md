# ymgui — Dear ImGui frames as compositor figures

ymgui bridges a client application running Dear ImGui with the yetty
compositor. The client renders its ImGui draw data into a binary wire format;
the receiving terminal hosts each placed sub-region as a
`yetty_ymgui_figure` — a [yclass](../yclass/README.md) class with parent
`yfigure:figure` — that draws the decoded mesh (vertices/indices/commands +
R8 font atlas) through one shared WebGPU pipeline. Figures hang off the root
[`yfigure`](../yfigure/README.md) container, are anchored to a rolling row,
and scroll with the surrounding terminal text.

Note on naming: the wire header still says "card" for a placed figure — that
word survives only on the wire (`YMGUI_OSC_CS_CARD_PLACE`, struct
`yetty_ymgui_wire_card_place`); the unit is a **figure** everywhere else.

## Wire model (`include/yetty/ymgui/wire.h`)

Hand-written C header shared by the C++ frontend and the C backend
(`YMGUI_WIRE_VERSION` = 4). One frame = a `yetty_ymgui_wire_frame` header
followed by per-cmd-list blocks (`cmd_list_hdr + vtx + idx + cmds`); vertex
layout is exactly ImGui's `ImDrawVert` (20 B). Two delta encodings keep
steady-state traffic small:

- `YMGUI_CMDLIST_FLAG_REPEAT` — slot byte-identical to last frame; only the
  16 B header travels.
- `YMGUI_CMDLIST_FLAG_CMD_DIFF` — per-cmd content hashes plus only the
  changed cmds inline; the receiver reassembles from its cached slot.

Client→server traffic now travels as typed yfigure yclass-RPC calls:
`yetty_yfigure_apply_child_body` bodies are self-describing sub-records
(`YETTY_YMGUI_FIGURE_SUB_FRAME`, `SUB_TEX_UPLOAD`, …; the magic-prefixed
legacy payloads are still accepted). The `YMGUI_OSC_CS_*` codes
(610000-range) are the legacy producer fallback. Server→client input events
(mouse, key, resize, focus) live in `<yetty/yterminal/client-input.h>`.

## Backend (receiver side)

| file | role |
|------|------|
| `figure.c` | annotated yclass figure: owns frame bytes (delta-rehydrated at `set_frame`), atlas texture, per-instance vtx/idx/uniform buffers + bind group; renders with viewport/scissor from the figure rect |
| `pipeline.c` / `pipeline.h` | shared WebGPU pipeline + sampler for all ymgui figures on a compositor; built lazily on first ymgui traffic, reads `ymgui-layer.wgsl` from the shaders dir |
| `ymgui-layer.wgsl` | the shader: frame-local pixel coords → NDC, atlas-sampled, premultiplied-alpha blend |
| `figure.gen.c`, `rpc.gen.c`, `model.yaml` | GENERATED by `make codegen` — never hand-edit |

`include/yetty/ymgui/figure.h` is also generated. Key entry points:

```c
struct yetty_ymgui_figure_ptr_result fig_res =
    yetty_ymgui_figure_create_local(rect, pipeline, context);
yetty_ymgui_figure_set_atlas(obj, atlas_bytes, atlas_size, atlas_w, atlas_h);
yetty_ymgui_figure_set_frame(obj, frame_bytes, frame_size);
/* Host wiring: */
yetty_ymgui_register_factory(registry, &factory_args);
```

## Frontend (client side, `frontend/`)

`ymgui_frontend` is the library a client app links (never linked into yetty
itself): `imgui_impl_yetty.cpp/.h` is a Dear ImGui renderer + platform
backend, `ymgui_encode.c/.h` the non-blocking PTY write queue. Envelope
framing/base64/LZ4F comes from [`yface`](../yface/README.md); the event loop
from [`yclient`](../yclient/README.md). Per-figure lifecycle:

```c
ImGui_ImplYetty_Init();
ImGui_ImplYetty_PlatformInit();                 /* raw stdin + DEC subscribe */
ImGui_ImplYetty_CreateFigure(figure_id, col, row, w_cells, h_cells);
/* per frame: */
ImGui_ImplYetty_BeginFigureFrame(figure_id);
ImGui::NewFrame(); /* … */ ImGui::Render();
ImGui_ImplYetty_RenderFigureDrawData(figure_id, ImGui::GetDrawData());
```

Each figure carries its own `ImGuiContext` (own DisplaySize, atlas, focus);
vertex coordinates are figure-local pixels.

## Consumers

- `demo/ymgui/01_demo_window` — the ImGui demo window running in a pane.
- `tools/ycompositor-ygui` — compositor host exercising ymgui alongside ygui.
- `yterminal/terminal.c` — receiver: creates figures as children of the root
  container, tracks the focused figure, routes mouse/key envelopes back to
  the client (the old dedicated ymgui layer is gone).

See [layered rendering](../../../docs/layered-rendering.md) for where figures
sit in the frame, and [`ygui`](../ygui/README.md) for the native (non-ImGui)
widget toolkit.
