# yshadertoy — Shadertoy-style user WGSL shader, as figure and as prim

yshadertoy runs a user-supplied WGSL `mainImage(...)` over a rectangle with
the familiar Shadertoy inputs (`iResolution`, `iTime`, `iTimeDelta`,
`iFrame`, `iMouse`) injected as uniforms. It ships in two tiers: a
positioned **figure** on the compositor wire (a `yfigure:figure` subclass)
and a cursor-anchored **prim** on the ordinary `YDRAW_BIN` drawable-list
channel that scrolls with the terminal text. Depends on `yfigure`,
`yrender`, `yframework`, `yevent` (figure tier) and `ydraw-list` /
`ydraw-factory` (prim tier).

## The shader contract

Both tiers take the same user text — just a `mainImage` function:

```wgsl
fn mainImage(fragCoord: vec2<f32>, iResolution: vec3<f32>,
             iTime: f32, iMouse: vec4<f32>) -> vec4<f32> { ... }
```

`fragCoord` is in pixels with the origin at the bottom-left of the rect
(Shadertoy convention). The receiver wraps the text with a full-rect vertex
shader and an `fs_main` that reads the injected uniforms
(`uniforms.yshadertoy_iTime`, …) and calls `mainImage`. When no shader is
set yet, a built-in animated-gradient default renders — never a blank rect.

## Figure tier (`figure.c`)

A yclass class (`class@yshadertoy:figure`, parent `yfigure:figure`). GPU
plumbing follows the shader-glyph pattern: a self-owned
`gpu_resource_binder` compiles the assembled WGSL lazily on first render.
An animation timer on the borrowed event loop ticks at the configured FPS,
marks the figure dirty and requests a render so `iTime` advances; it stops
on destroy. Two creation paths share the implementation:

```c
/* Direct, in-process (shader text up front; NULL = default gradient). */
struct yetty_yclass_object_ptr_result yetty_yshadertoy_create(
    struct yetty_ycore_rectangle rect, const char *shader_src,
    size_t shader_len, const struct yetty_context *context);
struct yetty_ycore_void_result yetty_yshadertoy_set_source(
    struct yetty_yclass_object *obj, const char *shader_src, size_t shader_len);

/* Wire path: registered under kind token "yshadertoy" by yframework's
 * register_figure_factories; the shader text arrives later as the
 * CREATE_CHILD init payload via process_bytes (the ygui widget drives this). */
struct yetty_ycore_void_result yetty_yshadertoy_register_factory(
    struct yetty_yfigure_registry *registry);
```

The public header `include/yetty/yshadertoy/figure.h`, `figure.gen.c`,
`rpc.gen.c` and `model.yaml` are **generated by `make codegen`** — see
[../yclass/README.md](../yclass/README.md).

## Prim tier (`prim.c`, `prim-wire.c`)

Type id `YETTY_YSHADERTOY_PRIM_TYPE_ID` (`0x80000007`), same complex-prim
tier as yplot / yimage / yvideo. Wire payload: 4×f32 bounds, u32 flags,
u32 wgsl_len, then the WGSL text padded to a word boundary. Two libraries,
mirroring yvideo's split:

- `yetty_yshadertoy_core` (`prim-wire.c`) — CPU-only serializer +
  one-call drawable-list builder (`yetty_yshadertoy_prim_render`); linked by
  client tools (ycat).
- `yetty_yshadertoy_prim` (`prim.c`) — the receiving concrete factory
  (`yetty_yshadertoy_prim_factory_create`). No shared pipeline exists for
  this type: the payload IS the shader, so each instance compiles its own.

## File map

| file | role |
|------|------|
| `figure.c` | annotated figure implementation (binder, uniforms, anim timer) |
| `figure.gen.c` / `rpc.gen.c` / `model.yaml` | codegen output — do not edit |
| `prim-wire.c` | wire serializer + drawable-list builder (CPU-only) |
| `prim.c` | concrete factory: per-instance WGSL compile + render |
| `demo-shaders.c` | built-in shader gallery (adapted from the `0xeff*` fractal glyph shaders); compiled directly into ygreeter / yhello / `demo/ygui/41_yshadertoy`, not into the module libraries |

## Consumers

- `../yframework/yframework.c` — registers the figure factory (ungated).
- `../ygui/widgets/yshadertoy.c` — the ygui widget minting the figure over
  the wire.
- `../ycat/handler-shadertoy.c` — `.wgsl` mainImage file → prim envelope
  (gated on `YETTY_YCAT_HAS_YSHADERTOY`).
- `../ydraw/scrolling-canvas.c` — registers the receiving prim factory.
- `tools/ygreeter`, `tools/yhello` — the demo gallery tab.
